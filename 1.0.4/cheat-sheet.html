Capture categories

Object Transforms
Stores each object’s location, rotation and scale, plus its shape-key values. On restore they’re written straight back. One of the heavier categories on big scenes, because it touches every object in scope.
Visibility & Display
Stores whether each object is hidden in the viewport and in renders, along with its display settings. Also covers collections — their visibility, whether they’re excluded from the view layer, and their colour tag.
Shader Nodes
Stores each object’s material slots and rebuilds every material’s node tree on restore. This is the materials category. It does not include the insides of node groups — those are a separate category, because they’re shared. Heavy.
Node Group Internals
Stores the internal node tree of every node group and rebuilds them on restore. Node groups are shared data in Blender, so restoring one affects every material and object using it — not only the ones in your scope. Heavy, and the one to be deliberate about.
Camera
Stores which camera is active, and whether the viewport is looking through it. Nothing else. The camera’s position, lens and depth of field belong to Views, not captures.
Modifiers
Stores each object’s whole modifier stack and its particle systems, and rebuilds them on restore. Heavy.
Lights
Stores light data: type, colour, energy, shadow settings, shape, shader nodes and light-linking. Where a light is and whether it’s visible come from Transforms and Visibility instead.
World
Stores the world background — colour, environment texture and its shader nodes.
Render Properties
Stores render settings: engine, sampling, resolution, colour management and frame range.
Compositor Nodes
Stores the scene’s compositing node tree and rebuilds it on restore. Scene-wide — there’s no way to scope it to particular objects.
Custom Properties
Stores custom properties on objects and collections.
Drivers
Stores drivers on objects, lights, cameras, the scene, the world, materials and node groups. Restoring also removes any drivers added since the capture, so the setup matches exactly. Drivers on bones, shape keys and vertex groups are never touched.

Buttons

Main panel
  • Latest — back to the scene as it was before you restored
  • Refresh — apply the selected capture again
  • Solo Mode — hide everything except this capture’s objects
  • Duplicate — copy the capture
  • Thumbnail — retake the preview image
  • Edit — restore for editing, click again to save
  • Override — overwrite chosen captures with the current scene
  • Lock — protect the name, data and thumbnail
  • Delete — remove the capture
Views panel
  • Add / Remove — add or delete a view
  • Go to View — move the camera there and look through it
  • Duplicate — copy the view
  • Save — write the camera’s current state into the view
  • Revert — discard changes and restore the stored view
  • Lock — refuse Save and Revert
  • Select Camera — select it in the viewport
  • Lock Camera to View — moving the viewport moves the camera
  • Duplicate Camera — copy the camera with all its views
  • Delete Camera — remove the camera and its views
Render panel
  • Add Job — create a new render job
  • Run All — render every job’s queue
  • Contact Sheet — grid of every shot across all jobs
  • Skip Existing — don’t re-render files already on disk
  • Render Setup — variants, profile and output for one job
  • Render Job — run this job on its own
  • Duplicate Job / Delete Job — copy or remove a job
  • Export All to Farm File — one .blend with a scene per shot, no Keep it needed
  • Output folder — open it in your file browser
  • Render Settings — render environment options
Contact sheet cell
  • Apply — restore this shot onto the scene
  • Render Thumbnail — re-render this cell’s preview
  • Edit — tweak the shot, then save or discard an override
  • Reset — remove the cell’s override
  • Base capture — choose what this cell composes on top of
  • Checkbox — include or exclude the shot from the render
